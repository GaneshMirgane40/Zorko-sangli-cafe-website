## 4. Decisions (details in DECISIONS.md)

- **Versions pinned (ADR-002):** Next 16.4.0, React 19.3.0, **TypeScript 5.9.3** (the official template uses `^5`; TS 7 not used), **ESLint 9.39.5**, Tailwind 4.3.3, Zod 4.6.7, Vitest 5.0.4, Playwright 1.64.0.
- **Cache Components on:** the Next 16.4 default. Request data must be read inside `<Suspense>`; the style guide already uses this pattern, as the menu will. See ADR-013.
- **Error boundaries use `retry()`**, the Next 16.2+ API.
- **Headings default to Sora** via the base layer. Stitch put a font class on every heading.

**Test fixes (test bugs, not code bugs — each explained, none weakens a requirement):**
- A meaningless regex assertion on `script-src` was removed. The real check (Supabase never allowed in `script-src`) remains.
- The `rounded-full` assertion was changed from an exact string to "≥ 9999px", because browsers report `calc(infinity*1px)` as a large number.
- Keyboard tests use **Option+Tab in WebKit**, matching Safari's default where Tab moves only between form fields. This was verified with a probe test before changing.
- The dialog test opens the dialog with the keyboard. Focus restore matters for keyboard users, and Safari doesn't focus buttons on mouse click.

## 7. Security checks and findings

- **Headers verified on both engines.** CSP is the documented "Without Nonces" variant: `'unsafe-inline'` scripts remain residual risk R-07, evaluated in Phase 7 (ADR-016).
- **Secret scans:**
  - Client bundle: 0 matches for secret names or values.
  - gitleaks on the project files: 0 findings. Its 8 hits are only in the git-ignored `.next/` (per-build Next.js preview/encryption keys).
  - gitleaks on the git history: **no leaks** (6 commits).
- **`npm audit --omit=dev`:** 0 vulnerabilities.
- **Full `npm audit`:** 5 "high", all one **dev-only** chain to `braces@3.0.3` (GHSA-vfj7-8cjw-p6xm, published 2026-09-18, **no patched version exists**). It's used only by ESLint on our own globs. Accepted and documented (ADR-032, R-12). npm's suggested downgrade of the ESLint config to v14 was rejected.
- **No secrets anywhere:** no `.env` file was read or created, and none is needed in Phase 2.

## 9. Known issues / limitations

- No database, auth or real pages yet. The home page plainly says "Website under construction".
- `/dev/styleguide` in a **production** build needs `ENABLE_STYLEGUIDE=true` for both `npm run build` and `npm start`, because the flag is re-checked per request. In `npm run dev` it is always available.
- **Your machine — your choice:** 4 files in your npm cache (`~/.npm/_cacache`) are owned by another user. This caused the lockfile problem. To fix it once, run `sudo chown -R $(whoami) ~/.npm`. I didn't run this (it's a system folder and needs your password).
- **`unrs-resolver` install script:** npm 11 reports that this package's install script was not run. Lint works without it (verified), so it is left unapproved.
